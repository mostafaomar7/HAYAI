# Website release `62e97fa` — deploy guide (2026-11-26)

Follows `a1d245f`. Same package shape, **no environment change**: replace the
two folders and restart. Section 2 is the whole job.

**If `a1d245f` (Website 2026) is not deployed yet, deploy this one instead:**
it contains everything in `a1d245f`, and that release's after-deploy steps
(`website-release-a1d245f.md`, section 4) still apply.

The site is server-side rendered: a Node process under Supervisor with nginx
in front, not a folder of static files. Never put it in `public_html`.

**Dashboard only** (Hayai points). Nothing on the public site changes. The API
side of both features is already live on production.

- **AI tokens with points** (backend prompt 2026-11-24).
- **Promo codes** (backend prompt 2026-11-26).

## 1. The package

`hayai-web-62e97fa.tar.gz` (also as `.zip`, with identical content):

```
hayai-web/
  browser/     static files
  server/      server.mjs and its chunks
  RELEASE      62e97fa…
  DEPLOY.md    this file
```

Self-contained: no `npm install`, no `node_modules`. Node 20 or newer.

## 2. Deploy

```bash
cd /tmp && tar -xzf hayai-web-62e97fa.tar.gz

sudo rm -rf /var/www/hayai-web.prev
sudo cp -r /var/www/hayai-web /var/www/hayai-web.prev

sudo rm -rf /var/www/hayai-web/browser /var/www/hayai-web/server
sudo cp -r /tmp/hayai-web/browser /tmp/hayai-web/server /var/www/hayai-web/
sudo cp /tmp/hayai-web/RELEASE /var/www/hayai-web/RELEASE
sudo chown -R www-data:www-data /var/www/hayai-web

sudo supervisorctl restart hayai-web
sudo supervisorctl status hayai-web          # RUNNING
```

Do **not** extract over the running tree: delete the two folders first.

**Rollback:** copy `browser/` and `server/` back from `/var/www/hayai-web.prev`,
run `chown`, and restart.

## 4. After the deploy (the admin, when ready)

- **AI tokens:** set the rate and limits, test with a pilot account (allowed
  while the switch is off), then switch it on.
- **Promo codes:** create one code per advertiser / influencer.

## 5. What changed since `a1d245f`

One code commit, `62e97fa`.

**AI tokens with points**
- Settings card: confirmed on/off switch (pilot accounts can use it while
  off), the rate as one sentence with both numbers editable, minimum and
  maximum per exchange (empty maximum is sent as `null`), its own Save that
  sends only what changed, API 422 shown under each field.
- New read-only page `/dashboard/loyalty/ai-exchanges`: date, member (links
  to the points account), points, tokens, rate at the time, tokens used;
  filters member id and dates, kept in the URL.
- Overview card from `ai_exchanges`; AI allocations show the
  `loyalty_points` source as "Bought with points".

**Promo codes** (`/dashboard/loyalty/promo-codes`)
- List: search, status and audience filters, copy button, uses ("∞" without
  a limit), points awarded, on/off switch.
- Form: the code is upper-cased without spaces or dashes as it is typed
  (empty = generated by the server); empty optional fields are sent as
  `null`; 422 per field ("This code is already taken.").
- Delete: an active code first offers "switch it off" (reversible) or
  "delete"; a used code is archived and the toast says so.
- "Used by" page per code, which works for archived codes too.
- Overview card from `promo_codes`.

Tested in the browser in Arabic and English against production reads. The
empty lists were tested with mocked rows. Every write was intercepted, so
nothing was written to production, and the AI switch is still off.
